Why is the baseline functional level Windows Server 2008 R2?

Pure Samba 4 Active Directory domain controllers run at the Windows Server 2008 R2 functional level for DRS replication stability and cross-vendor compatibility. Windows 10/11 clients, modern RSAT tools, AES-256 Kerberos, and Server 2016/2019 schema extensions remain fully supported on this baseline. Raising the functional level to native 2016 requires Windows Server 2016+ DCs holding the Schema Master role.

Kerberos 5-Minute Maximum Clock Skew Tolerance

Active Directory Kerberos V5 tickets (KRB_AP_REQ) include an encrypted timestamp. If a client workstation's clock drifts by more than 300 seconds (5 minutes) from this Domain Controller, Kerberos authentication is immediately rejected with KRB_AP_ERR_SKEW.

Windows clients joined to the domain should point their Windows Time service to this appliance:

w32tm /config /manualpeerlist:"<appliance-ip>" /syncfromflags:manual /reliable:YES /update

How Integrated Sysvol Replication Works

Unlike standard Linux sync utilities which corrupt Windows NT security descriptors, ZclockID integrates a SHA-256 tree synchronizer and the NTACL Guardian daemon. Whenever a policy is created in Windows RSAT (gpmc.msc) on any DC, files stream over encrypted HTTPS to peer nodes, and samba-tool ntacl sysvolreset is automatically fired to guarantee that Windows clients receive valid GPOs without Access Denied (Event ID 1058) errors.

Why Native Linux Sync?

Traditional setups require running a dedicated Windows Server VM solely to host Microsoft Azure AD Connect / Cloud Sync agent, costing thousands in Windows Server CALs.

ZclockID uses an asynchronous daemon (zclock-azuresync) communicating directly with Microsoft Graph REST endpoints over outbound TLS 443, eliminating external Windows dependencies entirely.

Forest level cannot exceed Domain level. Governs cross-forest trusts and catalog replication

                


                

                    
                         Functional Level Notice:
                    
                    
Pure Samba 4 Active Directory domain controllers run at the Windows Server 2008 R2 functional level for DRS replication stability and cross-vendor compatibility. Windows 10/11 clients, modern RSAT tools, AES-256 Kerberos, and Server 2016/2019 schema extensions remain fully supported on this baseline. Raising the functional level to native 2016 requires Windows Server 2016+ DCs holding the Schema Master role.

DNS-over-HTTPS (DoH) Setup Guide

                        
Configure RFC 8484 secure encrypted DNS on workstations and browsers

                    

                

                
            


            

                
                

                    Target Ingress Endpoints
                    

                        

                            

                                LAN / IP URL
                                https://<appliance-ip>/dns-query
                            

                            
                        

                        

                            

                                FQDN / TLS URL
                                https://<hostname.domain>/dns-query
                            

                            
                        

                    

                


                
                

                    

                        
                        Windows 11 Native OS DNS-over-HTTPS
                    

                    
    
                        
  1. Open Settings → Network & internet → Ethernet or Wi-Fi.
    2. 
                        
  2. Click Edit next to DNS server assignment and switch to Manual.
    3. 
                        
  3. Toggle IPv4 ON. Set Preferred DNS to appliance-ip.
    4. 
                        
  4. Under DNS encryption, select Encrypted only (DNS over HTTPS) or Encrypted preferred.
    5. 
                        
  5. In the DNS-over-HTTPS template box, enter:
                            
    
                                https://<hostname.domain>/dns-query
                                
                            
    
                        
    6. 
                    

                


                
                

                    
                    

                        

                            
                            Google Chrome
                        

                        
    
                            
  1. Go to chrome://settings/security
    2. 
                            
  2. Enable Use secure DNS
    3. 
                            
  3. Choose With: Custom and paste:
    4. 
                        

                        

                            https://<hostname.domain>/dns-query
                            
                        

                    


                    
                    

                        

                            
                            Mozilla Firefox
                        

                        
    
                            
  1. Go to Settings → Privacy & Security
    2. 
                            
  2. Under DNS over HTTPS select Max Protection
    3. 
                            
  3. Select Provider Custom and enter:
    4. 
                        

                        

                            https://<hostname.domain>/dns-query
                            
                        

                    

                


                
                

                    

                        

                            
                            Linux & macOS curl RFC 8484 Test
                        

                        
                    

                    
curl -k -H "accept: application/dns-message" "https://<appliance-ip>/dns-query?dns=..." --output /dev/null -w "HTTP %{http_code} | Time: %{time_total}s\n"
